# C4 OUT — recherche web multi-fournisseurs

Date : 2026-09-19, Europe/Paris  
Lane : C4 — Web multi-fournisseurs

## Cause prouvée avant correctif

Le test rouge `test_zero_resultat_searxng_declenche_le_repli_tavily` a rejoué
le cas observé : SearXNG répond HTTP 200 avec `{"results": []}` (CAPTCHA côté
moteurs). Avant ce lot, `SearXNGSearch.search()` rendait alors
`(True, "Je n'ai rien trouve sur ce sujet.")`. `WebSearch` interprétait ce
booléen comme un succès et retournait immédiatement ce texte ; Tavily n'était
pas appelé. Sortie du test rouge : attendu « Reponse Tavily apres CAPTCHA. »,
obtenu « Je n'ai rien trouve sur ce sujet. ».

## Correctif livré

- `src/brain/tools_web.py` : une réponse vide est désormais non utilisable et
  poursuit la chaîne : SearXNG → DuckDuckGo (`ddgs`) → Tavily → Brave → Exa →
  Jina → Serper.
- Les fournisseurs HTTP ont des squelettes injectables/testables, avec leurs
  formats de requête et la normalisation vers le contrat vocal existant.
- `ddgs` est importé paresseusement et ajouté à `requirements-extra.txt` : son
  absence ne bloque pas le démarrage, la chaîne continue.
- Les clés ne sont lues que depuis l'environnement : `TAVILY_API_KEY`,
  `BRAVE_API_KEY`, `EXA_API_KEY`, `JINA_API_KEY`, `SERPER_API_KEY`.
  Aucune valeur n'est dans le dépôt, les journaux ou ce document.
- `.env.example` et la whitelist du host-agent incluent ces noms. Une seule
  clé de repli suffit désormais à exposer `web_search` si SearXNG n'est pas
  configuré.
