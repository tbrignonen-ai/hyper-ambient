# NOTE JeV v2

## Ce qu'est vraiment JeV (vérifié le 19/09)
- TypeSafe AI, « System One model » : **nouvelle architecture** + échantillonneur parallèle ; renvoie des
  **valeurs typées avec probabilités calibrées** ; « n'écrit pas de réponses, ne produit pas de code ».
  Latence annoncée 70–500 ms. Early access, **API seulement**, aucune mention de poids ouverts.
  Sources : https://typesafe.ai/blog/introducing-system-one-models-and-jev · https://docs.typesafe.ai/concepts/system-one
- **La veille WS se trompait de catégorie** : SmolLM2, Qwen3-0.6B, TinyLlama… sont des LLM génératifs
  classiques, pas des modèles « System One ». Un petit LLM + grammaire n'a ni la calibration ni l'architecture.
- Équivalent local le plus proche trouvé : **OpenJev / Verdict** (tiers, non officiel) — ModernBERT-base + tête GLiClass,
  151 M paramètres, choix + confiance calibrée + abstention, p50 35,6 ms CPU, Apache-2.0, **anglais seulement**.
  https://github.com/Heman10x-NGU/Verdict-open-jev

## Usages candidats d'un « System One » local (à discuter, rien de décidé)
1. **Fin de tour** — l'utilisateur a-t-il fini de parler ? (MOTHER ne coupe plus / répond plus tôt). Peut être déjà couvert par l'oreille (Kyutai STT a un « semantic VAD » intégré).
2. **Est-ce qu'on me parle ?** — adressé à MOTHER ou conversation autour (condition du « sans les mains »).
3. **Vraie interruption ou simple « mmh »** — distinguer « stop / attends » d'un acquiescement pendant qu'elle parle.
4. **Ton de la réponse** — choisir un style de voix (calme / enjoué) selon la demande.
5. **Confirmation calibrée** avant une action locale sensible, avec abstention si incertain.
