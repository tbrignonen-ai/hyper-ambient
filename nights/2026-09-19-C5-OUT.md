# C5 — Voix distante : étude et squelette MOUTH

## Verdict

**GO comme intégration optionnelle, pas comme voix primaire temps réel.**

Le contrat `POST /audio/speech` est assez proche du contrat MOUTH existant pour
un adaptateur isolé. StepAudio 2.5 TTS a déjà été mesuré aujourd'hui à environ
3,8 s par phrase : il peut apporter une autre qualité/voix, mais il est beaucoup
trop lent pour remplacer Magpie Sofia dans la boucle ambiante. Le chemin distant
doit donc rester un choix explicite et réversible.

Le squelette est prêt dans `src/mouth/remote_tts.py`. Il ne charge **aucun**
modèle local, n'importe ni `torch` ni un backend MOUTH local, ne lance aucun
processus et ne sonde pas CUDA. Il n'a donc aucun effet sur Magpie Sofia tant que
le sélecteur live n'est pas modifié.

## Preuve StepFun au 19 septembre, ~20 h 05

Probe GET uniquement, sans génération audio et sans afficher la clé ni le corps
des réponses :

| Route | HTTP | Résultat utile |
|---|---:|---|
| `STEPFUN_BASE_URL/models` | 200 | `stepaudio-2.5-tts` présent |
| `STEPFUN_BASE_URL/audio/voices` | 200 | schéma `object,data,has_more,first_id,last_id`, mais `data=[]` |

La voix déjà vérifiée lors du banc reste
`elegantgentle-female`. Elle figure dans `.env.example` comme **exemple de
configuration**, pas comme catalogue codé en dur. Le catalogue doit venir du
fournisseur après validation de la clé. Quand le fournisseur renvoie un
catalogue vide ou interdit son accès, une voix explicitement configurée reste
utilisable ; l'UI devra dire que la liste n'est pas disponible au lieu d'en
inventer une.

Sources publiques consultées : [plateforme StepFun](https://platform.stepfun.com/),
[contrat officiel OpenAI `POST /v1/audio/speech`](https://platform.openai.com/docs/api-reference/audio/createSpeech),
[exemple d'un catalogue fournisseur distinct chez ElevenLabs](https://elevenlabs.io/docs/api-reference/voices/search).

## Ce qui est implémenté

- configuration générique `MOUTH_REMOTE_*`, avec alias des secrets/URL
  `STEPFUN_API_KEY` et `STEPFUN_BASE_URL` ;
- probe d'authentification non facturant via `GET /models` ;
- récupération best-effort de `GET /audio/voices`, avec parsing des formes
  `data`, `voices`, `id`, `voice_id` et `name` ;
- synthèse `POST /audio/speech` avec `model`, `voice`, `input` et
  `response_format=wav` ;
- décodage WAV PCM 16 bits mono/stéréo vers le PCM `numpy.int16` attendu par le
  host-agent ;
- contrat `load_model`, `synthesize`, `synthesize_stream`, `close` compatible
  avec les autres MOUTH ;
- découpe du flux texte par phrase et respect de `flush=True` ; ce n'est pas du
  streaming audio intra-phrase : chaque requête reçoit un WAV entier ;
- repli local **injecté seulement** : `RemoteTTS` peut appeler une instance déjà
  possédée par l'orchestrateur, mais ne la crée, ne la charge et ne la ferme
  jamais ;
- erreurs journalisées par leur type seulement : aucune clé, aucun en-tête et
  aucun corps de réponse dans les logs ;
- variables et exemple StepAudio documentés dans `.env.example`.

## Configuration proposée

```dotenv
MOUTH_BACKEND=remote
MOUTH_REMOTE_BASE_URL=https://api.stepfun.ai/step_plan/v1
MOUTH_REMOTE_API_KEY=
MOUTH_REMOTE_MODEL=stepaudio-2.5-tts
MOUTH_REMOTE_VOICE=elegantgentle-female
MOUTH_REMOTE_TIMEOUT_S=30
```

`MOUTH_REMOTE_BASE_URL` / `MOUTH_REMOTE_API_KEY` peuvent être omis si les alias
`STEPFUN_BASE_URL` / `STEPFUN_API_KEY` existent. Les routes sont surchargeables
pour un fournisseur compatible : `MOUTH_REMOTE_AUTH_PATH`,
`MOUTH_REMOTE_VOICES_PATH`, `MOUTH_REMOTE_SPEECH_PATH`.

## Limite de compatibilité fournisseur

Le squelette couvre les API compatibles OpenAI sur la synthèse. « N'importe
quel fournisseur » ne veut pas dire « aucune adaptation » : ElevenLabs, par
exemple, utilise une route, un en-tête d'authentification, un format de sortie et
un catalogue différents. L'étape suivante propre est une petite stratégie de
fournisseur (`OpenAICompatibleProvider`, puis `ElevenLabsProvider`, etc.), pas
une accumulation de conditions dans `RemoteTTS`.

## Branchement live volontairement différé

Le bloc MOUTH de `dev/scripts/serve_hostagent.py`, `src/mouth/magpie_tts.py` et
`src/mouth/normalize.py` étaient réservés/modifiés pendant le test live Sofia.
Je ne les ai pas touchés. Le raccord, une fois ce bloc libéré, est minimal :

```python
elif backend == "remote":
    from src.mouth.remote_tts import RemoteTTS

    self.tts = RemoteTTS.from_env()
```

Cette branche doit précéder le `else` Piper. Avec cette forme, choisir
`MOUTH_BACKEND=remote` garantit **zéro chargement GPU local**. Pour un repli
automatique, injecter uniquement une voix locale déjà chargée, ou rendre le
backend de repli explicite (`none`/CPU/Magpie) ; ne jamais démarrer Magpie en
secret derrière le backend distant.
