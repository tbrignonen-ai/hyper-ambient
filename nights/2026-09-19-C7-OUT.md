# C7 — OUT

Document produit : [`2026-09-19-C7-NATIF-WINDOWS.md`](2026-09-19-C7-NATIF-WINDOWS.md).

## Résultat

Le portage de Hyper Ambient vers **Windows x64 natif sans Docker/WSL est faisable**. Les voies officielles existent pour llama.cpp CUDA, faster-whisper/CTranslate2, sherpa-onnx et, contrairement à l'incertitude initiale, NeMo-Speech.cpp avec MagpieTTS sous Windows.

Architecture recommandée :

- lanceur/superviseur dans la session utilisateur, pas un Windows Service ;
- Python 3.11 embarqué et isolé ;
- moteurs BRAIN/EARS/MOUTH en processus séparés sur `127.0.0.1` ;
- conservation initiale de la frontière WebSocket du host-agent ;
- Job Objects séparés pour remplacer le plafond cgroup RAM ;
- budget VRAM applicatif via `nvidia-smi`/NVML ;
- modèles téléchargés au premier lancement vers un SSD choisi par l'utilisateur ;
- artefacts et modèles figés par version, taille et SHA-256.

## Points de vigilance

1. Le couple exact faster-whisper/CTranslate2/CUDA/cuDNN doit être verrouillé et testé comme un ensemble.
2. NeMo-Speech.cpp ne prend pas en charge sa normalisation de texte interne sous Windows : conserver la normalisation Hyper Ambient avant Magpie et valider Sofia en français.
3. Canary-1B-v2 n'est pas réputé compatible par simple transitivité avec NeMo-Speech.cpp ; preuve dédiée requise si cette oreille gagne.
4. Une limite mémoire Windows Job Object ne couvre pas la VRAM.
5. Les chemins Linux, scripts Bash et recherches de processus par `pgrep/ps` exigent une future couche de portabilité ; aucun de ces changements n'a été fait dans C7.

## Plan retenu

1. Figer versions, manifestes, chemins, ports et budgets.
2. Faire une preuve manuelle Windows native de chaque moteur puis un tour vocal complet.
3. Ajouter le superviseur et les Job Objects.
4. Construire l'installateur signé avec Python embarqué.
5. Télécharger les modèles au premier lancement, avec reprise et vérification SHA-256.
6. Qualifier sur une machine propre sans Docker, WSL, Python ni outils développeur.
