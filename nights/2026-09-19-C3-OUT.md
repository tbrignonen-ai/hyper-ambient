## Livré

Nouveaux fichiers uniquement :

- `src/ears/jev_reflexe.py`
- `dev/tests/test_jev_reflexe.py`

`JevReflexe` est autonome et n'est pas encore branché à EARS, au bouton, ni à
`serve_hostagent.py`. Une instance conserve un `httpx.AsyncClient` avec une
connexion HTTPS keep-alive ; son appel `evaluate(transcription, context=...)`
envoie exactement une requête `POST https://api.typesafe.ai/v1/systemone`,
modèle `jev-latest`, avec les 13 questions demandées.

Le résultat est soit une `JevEvaluation` (réponses typées brutes + signaux
filtrés), soit `None`. `None` est le repli silencieux, donc le futur branchement
peut conserver le comportement actuel du bouton sans convertir une erreur en
message utilisateur. Il s'applique sans clé, sur timeout, erreur HTTP/réseau,
JSON invalide ou réponse incomplète. La clé est lue dans `TYPESAFE_API_KEY` au
moment de `evaluate`, jamais affichée ni journalisée.

Le budget est plafonné à 600 ms, même si `JEV_TIMEOUT_MS` est plus haut. Les
seuils configurables sont :

- `JEV_NOUL_TRUE_THRESHOLD` (défaut `0.75`)
- `JEV_CHOICE_CONFIDENCE_THRESHOLD` (défaut `0.60`)
- `JEV_SCORE_CONFIDENCE_THRESHOLD` (défaut `0.60`)
- `JEV_TIMEOUT_MS` (défaut/plafond `600`)

Le harnais ressort seulement comme observation (`none`, `claude` ou `codex`) si
la confiance suffit. Aucun champ, routeur ou effet de bord n'envoie une tâche à
un harnais.

une requête d'amorçage hors parcours produit a ouvert la connexion : HTTP 200 en
701 ms. Les cinq transcriptions françaises réelles de la note oreille ont ensuite
été évaluées par le module sur cette même connexion :

| phrase | résultat | latence |
|---|---|---:|
| phrase1 | OK | 288 ms |
| phrase2 | OK | 328 ms |
| phrase3 | OK | 268 ms |
| phrase4 | OK | 344 ms |

confirmé le repli silencieux lorsque le budget est dépassé.
